# 免费关键词研究工作台 V1：侧边栏、今日新词与竞品监测需求

日期：2026-10-21
状态：待用户评审
适用仓库：`mingjobo/new-term-radar`
参考：[原免费平台设计](2026-10-15-free-keyword-platform-design.md)

## 1. 背景与目标

现有开发分支已验证 GitHub、Hugging Face → Neon → 网页的首次只读链路，但自动重复采集尚未启用。现有网页将新词、来源状态和基线放在同一首页，没有竞品网站的页面增减清单。

本版重排**现有的 Term Signal 关键词研究网站**，不是另建竞品站。桌面端采用左侧功能导航、右侧内容区：左侧依次为“总览／关键词看板／设置”；关键词看板右侧顶部再切换“新词／竞品”。新词页专注当天更新与逐条线索，原有“查看出处／研究卡”操作保留；竞品页展示多个网站**哪些网址新进入、哪些网址移出站点地图**；基线与竞品网站输入移入设置。首个试点网站是 [aiphotoeditor.com](https://aiphotoeditor.com/)；2026-10-21 读取其 [robots.txt](https://aiphotoeditor.com/robots.txt) 可找到 [Sitemap](https://aiphotoeditor.com/sitemap.xml)，当时 Sitemap 列出 139 个网址。这个数字是现场观察，不是写死的产品目标。

“移出”在 V1 中只有一个含义：某网址存在于该站点上一次完整的 Sitemap 快照，却不在本次完整快照中。系统不据此声称网页已删除或返回 404。首次采集只建基线，不产生新增或移出事件。

## 2. 用户与成功标准

用户是个人研究者，需要在**同一个网站**里用左侧导航明确选择功能；总览默认看今天，也能切换日期回看当天结果。站点和页面数量可能很多，竞品页先汇总站点，不平铺所有页面事件；采集基线与配置不挤占新词页。

V1 完成时，用户应能在工作台回答：

1. 打开“关键词看板 → 新词”，今天新增多少词、多少条线索、最近何时更新？每条词的名称、来源、发现时间和操作在哪里？
2. 切到“关键词看板 → 竞品”，今天哪些站点有 URL 新增或移出，各有多少？点进站点后有哪些具体 URL？
3. 在“设置”里如何输入或暂停竞品网站，查看各来源的基线、运行状态和异常？
4. 在“总览”切换日期后，是否能看到所选日期的新词和竞品统计，而不是仍显示今天的数据？
5. GitHub/HF 与竞品采集是否按计划自动更新，失败时是否明确提示而不伪造变化？

## 3. 范围与交付顺序

| 阶段 | V1 交付 | 可验收结果 |
|---|---|---|
| A. 跑活现有来源 | GitHub、HF Models、HF Spaces 完成第二次实际采集，再接入每 8 小时自动运行 | 运行记录和网页时间更新；同一周期重跑不重复生词 |
| B. 多站点 Sitemap 监测 | 设置页可输入站点；每日读取各站完整 Sitemap；逐站保存基线并计算新增/移出 URL | 首次运行零事件；下一次完整运行产生准确差分；单站失败不影响其他站 |
| C. 工作台重排 | 左侧“总览／关键词看板／设置”；总览可切换日期；看板右侧“新词／竞品”；保留新词研究卡和原始出处操作 | 总览按所选日期更新；新词默认显示当天更新与列表、不出现基线卡；竞品先站点后 URL；设置可管理站点并查看基线 |
| D. 预览验收 | 在开发 Neon 分支及 Vercel 预览站点验证采集、读写隔离与界面 | 页面计数与数据库记录一致；非管理请求不能改设置；失败/不完整时无虚假移出 |

本需求覆盖并收窄原设计中 Sitemap 与工作台的 V1 范围。V1 先交付 URL 名单变化；原设计中的页面文字抓取、用途词推断、3/14 天复查及日报周报不属于本次验收。

## 4. 用户故事与验收条件

### US-001：在设置中输入竞品网站

作为研究者，我希望在“设置”输入竞品网站，而不是修改仓库文件或在竞品看板里找添加入口。

- [ ] 设置页可填写站点名称、主页 URL 和可选的 Sitemap URL；未填 Sitemap 时先按该站 `robots.txt` 声明发现。
- [ ] 可查看已监测站点并修改名称、Sitemap 地址，或暂停/恢复监测；暂停不删除历史记录。主页域名不能就地更换，换域名需暂停旧站并新增站点，避免把两站快照误作差分。V1 不提供永久删除。
- [ ] 提交时明确提示保存成功或 URL 无效；下一次定时采集若找不到 Sitemap，再将站点标为“无法监测”。保存配置本身不触发采集，也不把未成功建档的站点显示成“今日新增”。
- [ ] 各站点独立建立快照和显示状态；新增站点不会重置已有站点的历史。没有可用 Sitemap 的站点显示“无法监测”，不回退为全站爬取。
- [ ] 只有已认证的工作台所有者能修改设置；浏览和采集使用的凭据不能被网页表单读取。

### US-002：首次建档

作为研究者，我希望首次采集只记录当前网址，以免把存量页面误认为今天新增。

- [ ] 首次完整读取一个站点时保存 URL 名单、采集时间和网址总数。
- [ ] 此次新增数和移出数都为 0；“基线已建立，等待下次比较”显示在设置的站点状态中，竞品看板只显示“等待下次比较”，不展示基线数。
- [ ] 首次读取为空、失败、超出预算或只完成部分 Sitemap 时，不建立基线。

### US-003：识别新增和移出的网址

作为研究者，我希望看到两次完整采集之间的 URL 名单差异。

- [ ] 本次有、上次没有的 URL 记录为“新增页面”；上次有、本次没有的记录为“移出站点地图”。
- [ ] 每条事件保存站点、完整 URL、类型和**发现时间**；发现时间不标作网站实际发布时间。
- [ ] 同一采集周期重跑不产生重复事件；曾移出的 URL 后来重新出现，作为该次新增记录。
- [ ] 网址比较仅做保守规范化，避免主机名大小写、默认端口及片段标记产生假差异，不合并不同路径。

### US-004：异常时保护旧基线

作为研究者，我希望站点暂时不可访问时，工作台明确显示问题，而不是报告大量页面被移出。

- [ ] Sitemap 索引或任何必要分片读取失败、结果为空、格式异常或超过预算时，该站状态为失败或不完整，旧基线保持原样，新增/移出事件均不产生。
- [ ] 一个站点失败时，其他站点继续采集和提交。
- [ ] 每个站点在设置中显示最近一次成功时间、基线数与最近一次尝试状态；竞品看板对异常或过期站点显示简明提示，不把失败视作 0 变化。

### US-005：左侧功能导航与总览

作为研究者，我希望用固定的功能结构快速找到新词、竞品和设置。

- [ ] 桌面版左侧侧边栏自上而下只有一级入口“总览／关键词看板／设置”，右侧为当前功能详情；选中项明确高亮，切换时侧边栏保持位置。
- [ ] “总览”右侧顶部是可切换的日期，默认显示北京时间今天；可选择过去的日期，不允许选择未来日期。
- [ ] 日期下方只显示所选日期的新词数、线索数、有 URL 变化的竞品站点数、新增 URL 数和移出 URL 数。切换日期时五项统计一起更新；不放基线卡、完整事件列表或重复的功能跳转按钮。
- [ ] 统计按北京时间自然日计算；已成功采集且无新增显示 0，未采集或数据不可用显示“未采集”，不把缺失数据当成 0。总览的日期选择只影响总览，不改变看板页签当前的筛选。
- [ ] “关键词看板”右侧顶部直接显示“新词／竞品”两个页签，不再重复显示“关键词看板”标题；默认打开“新词”，刷新后保持所选页签。
- [ ] 右侧不同视图共用现有 Term Signal 色彩与排版；窄屏可折叠侧边栏但保留相同入口顺序，浏览器验收桌面与窄屏。

### US-006：今日新词页

作为研究者，我希望打开“关键词看板 → 新词”就直接看到今天更新了什么，再逐条查看线索。

- [ ] 页签下方直接显示北京时间“今天”的新增词数、今日线索数和最近一次成功更新时间；计数只针对新词来源，不混入竞品 URL。
- [ ] 页面不显示 GitHub/HF 的快照数量、基线卡或技术运行明细；这些信息仅在设置的来源状态中查看。
- [ ] 下方逐条列出今天发现的新词线索，至少显示名称、来源、发现时间；保留原有“查看出处 ↗”和“研究卡 →”操作及现有研究卡路径 `/terms/{id}`。
- [ ] 列表以“今天首次发现的词”为一行；同一词有多个来源时展示来源标签，研究卡保留全部证据。“今日线索数”按观测记录计，可能大于列表中的词条数。
- [ ] 今天没有新词时明确显示“今天暂无新词”，并区分“已成功采集但无新增”和“来源采集失败”；后者给出前往设置查看原因的入口。
- [ ] 多条线索可分页/继续读取；列表、链接和空状态均在浏览器中验收。

### US-007：竞品站点汇总页

作为研究者，我希望先看到站点级别的变化数量，以便在很多站点里找到最值得点开的站点。

- [ ] “关键词看板 → 竞品”右侧默认显示按站点排列的列表，列出站点名、选定时间范围内新增数、移出数、最近成功时间和状态；竞品输入与编辑只在设置，不在此页出现。
- [ ] 页签下方直接放筛选和站点汇总，不另加“竞品页面”等重复标题。
- [ ] 支持按站点名搜索、只看有变化站点、按状态筛选；默认按最近变化时间排序。
- [ ] 汇总页显示监测站点数、新增 URL 数、移出 URL 数和异常站点数；统计口径与列表一致。
- [ ] 站点很多时使用分页；浏览器实测窄屏仍可读，不把所有 URL 平铺在站点汇总页。

### US-008：竞品单站 URL 清单

作为研究者，我希望点进一个站点后快速找到具体 URL。

- [ ] 单站页面提供“新增”“移出站点地图”“全部”切换、URL 路径搜索、时间范围筛选和分页；每页默认 50 条。
- [ ] 每行显示发现时间、类型、可读的 URL 路径和“打开原始页面”链接；可查看完整 URL。
- [ ] Sitemap 不保证提供页面标题，V1 以 URL 路径为主标签，不为填标题而逐页抓取正文。
- [ ] 首次建档、没有变化、采集失败和无匹配结果分别显示明确的空状态；使用浏览器验收这些状态。

### US-009：设置中的来源状态

作为研究者，我希望在“设置”看到采集健康状况和基线，而不让技术信息占据新词页面。

- [ ] 设置页分别显示 GitHub、HF Models、HF Spaces 的上次成功时间、最近运行结果、当前基线数和本次新增数；竞品站点也在设置列表显示自己的基线数与运行状态。
- [ ] 来源失败、数据不完整、尚未运行、首次建档和正常运行有不同文案；查看状态不触发采集。
- [ ] 基线数量不在“总览”和“关键词看板 → 新词”出现；设置页数据与数据库运行记录一致。

### US-010：现有新词来源自动更新

作为研究者，我希望 GitHub/HF 数据自己更新，而不需要点击“研究”。

- [ ] GitHub、HF Models、HF Spaces 使用独立的免费任务每 8 小时运行；竞品 Sitemap 每日运行一次。
- [ ] 新词页继续展示有来源的词条；详细来源状态放在设置。
- [ ] 采集任务只使用平台写入凭据；普通看板查询继续使用数据库只读凭据，设置的写入单独限权。
- [ ] 免费任务不调用原上游工作流的付费 API；在预览环境先验证重复运行和故障状态。

## 5. 功能规则

- **FR-01：站点来源。** 竞品站点由设置页写入持久配置；每站有稳定标识和单独的 Sitemap 快照。支持多个站点，首批只启用 aiphotoeditor.com 进行真实验收。
- **FR-02：发现方式。** 仅读取公开 Sitemap；可处理普通 Sitemap 和 Sitemap 索引及其必要分片。遵守 `robots.txt` 与站点的抓取间隔。
- **FR-03：完整性。** 仅在该站所有必要 Sitemap 成功、格式有效且未超预算时提交新快照。部分成功不能用于计算新增或移出。
- **FR-04：差分。** `新增 = 本次 URL 集合 − 上次成功 URL 集合`；`移出 = 上次成功 URL 集合 − 本次 URL 集合`。首次成功只有快照，没有事件。
- **FR-05：移出语义。** “移出”只表示不在 Sitemap；不检查目标页面的 HTTP 状态，也不标记“已下线”。
- **FR-06：时间。** 事件时间是系统发现时间。数据库存带时区的时间；总览日期选择及界面“今天”按北京时间自然日计算。切换总览日期时，所有总览指标使用同一天的数据。
- **FR-07：隔离与去重。** 站点各自成功或失败；同一站点同一周期的同一 URL/类型最多记录一次。
- **FR-08：记录。** URL 快照、事件、运行状态持久保存在现有 Neon 平台。页面增减事件与关键词线索分开存放，不自动把 URL 路径当作有搜索需求的新词。
- **FR-09：站点汇总。** 先展示站点级计数和健康状态；具体 URL 只在单站清单出现。搜索、筛选和分页在服务器侧处理。
- **FR-10：页面链接。** 事件可回到原始 URL；移出事件的链接可能已不可访问，界面仍保留它作为原始证据。
- **FR-11：运行频率。** 现有 GitHub/HF 来源每 8 小时采集；Sitemap 站点每日采集。缺一次运行后只按真实最新时间重新读取，不编造错过时段的历史事件。
- **FR-12：读写边界。** 总览、看板和研究卡只查询已保存结果，不提供手动抓取。只有设置中的竞品站点管理允许经认证的有限写入；普通查询仍使用只读数据库角色，采集写入凭据不进入网页。
- **FR-13：统一信息架构。** 左侧固定一级入口“总览／关键词看板／设置”；进入关键词看板后，右侧顶部直接是“新词／竞品”页签，不重复显示“关键词看板”标题，默认“新词”。研究卡 `/terms/{id}` 保持可用并可返回看板；不另起网站。
- **FR-14：今日新词。** 新词页默认按北京时间当天展示新增词数、线索数、最近成功更新时间和逐条线索；每条含名称、来源、发现时间、原始出处与研究卡操作。来源基线数只在设置显示。
- **FR-15：竞品与设置分工。** 竞品页只做站点汇总、筛选和 URL 明细；新增、修改、暂停/恢复监测网站在设置页完成。暂停不删除历史，不生成移出事件。
- **FR-16：安全输入。** 设置写入必须校验外部 HTTP(S) 地址；采集时连同重定向目标一起阻止内网、回环和云元数据地址，限制请求范围，防止表单跨站提交。页面文本安全呈现，外部链接仅允许 HTTP(S)。

## 7. 技术约束与现有项目衔接

- 复用已有 Python 采集入口、请求预算、Neon 和 Vercel 部署；网页沿用 `radar_platform/templates/index.html`、`radar_platform/static/app.js`、`app.css` 的现有品牌样式，重排为侧边栏。竞品事件需要独立持久记录，不塞进 `radar_terms` 冒充关键词。
- 竞品站点清单 V1 由“设置”写入 Neon，定时采集任务从同一份持久配置读取；不再要求改仓库配置才能增添网站。站点变更在下一次计划任务生效，不承诺即时采集。
- 现有网页使用 Basic Auth 且只有只读数据库连接。设置写入需要单独的管理接口和仅可操作站点配置的数据库权限；不得把采集者写入凭据放进网页、浏览器或通用看板接口。仍是单人使用，不引入付费身份服务或多用户体系。
- 沿用原设计的单站安全上限：最多读取 20 个 Sitemap 文档、20,000 个 URL；超限标记不完整并保留旧快照。实际默认值及大站点行为须在实施计划中写出测试。
- 2026-10-21 所见 aiphotoeditor.com Sitemap 的 `lastmod` 值相同，因此 V1 不使用 `lastmod` 判断页面是否变化；只比较 URL 集合。
- 预览阶段先使用现有 Neon `dev-free-platform` 分支和 Vercel 预览部署。正式启用前验证采集凭据与网页只读凭据隔离。

## 8. 非目标

- 不比较已有页面的标题、正文、价格、图片或截图；不生成“变化前/变化后”内容对比。
- 不检查移出 URL 的 404/410，不推断实际下线时间。
- 不推断搜索量、SEO 难度或商业价值；不自动把页面路径转成关键词。
- 不抓取没有 Sitemap 的整站，也不登录竞品后台。
- 不做多用户管理、公开匿名添加站点、从竞品页添加站点、永久删除站点、手动抓取、通知推送、付费 API、3/14 天复查、日报周报或 GSC 集成。

## 9. 验收与成功指标

1. **真实建档：** aiphotoeditor.com 首次完整采集成功，保存当次实际 URL 数；新增和移出均为 0。重复执行同一周期没有事件。
2. **受控差分：** 测试快照中加入 3 个 URL、移去 2 个 URL，恰好得到 3 条新增、2 条移出；第三次同样快照得到 0 条。
3. **故障保护：** 分片缺失、空内容或预算耗尽时，旧快照版本和事件数不变；其他站点仍可成功。
4. **多站点可读：** 用至少 20 个站点、单站至少 1,000 条示例事件验收汇总、搜索和每页 50 条分页；汇总数与详情数一致。
5. **自动运行：** GitHub/HF 连续两次定时运行有真实记录；竞品站点连续两次每日运行有真实记录。站点无变化时显示 0，不伪造事件。
6. **导航与日期：** 浏览器中左侧只出现“总览／关键词看板／设置”；总览默认显示北京时间今天的日期，选择一个有历史记录的日期后五项统计都切换到该日；未来日期不可选，未采集与零新增能区分。
7. **今日新词：** 看板顶部切“新词／竞品”。新词默认显示今天的更新总览和“名称／来源／发现时间／查看出处／研究卡”，不出现基线卡；现有研究卡仍可打开和返回。
8. **竞品浏览：** 同一网站内从“关键词看板 → 竞品”进入站点汇总、单站清单和原始 URL；大量站点/事件可筛选分页，错误及首次建档文案正确，桌面与窄屏通过浏览器验收。
9. **设置与权限：** 在设置中添加 aiphotoeditor.com、修改并暂停/恢复一个测试站点，定时任务读取变更；来源基线/运行状态只在设置可见。未经认证或普通查询请求不能修改站点配置，浏览器不获得采集写入凭据；私网 URL 被拒绝。
