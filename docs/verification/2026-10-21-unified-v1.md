## Task 6 — settings writes through a separate role

- The settings API accepts only authenticated JSON `POST /api/settings/sites` and `PATCH /api/settings/sites/{id}` from an explicitly allowed Origin matching the request Host. Missing/cross-site Origin, changed homepage host, unexpected fields, non-JSON or oversized bodies are rejected. There is no delete or manual-crawl endpoint. A duplicate hostname yields a safe 409 response without database details.
- `RADAR_SITE_ADMIN_DATABASE_URL` is optional and has no writer fallback. Without it, settings writes remain disabled; when it is present, `RADAR_WEB_ALLOWED_ORIGINS` must also be configured. The preview's existing read-only configuration remains valid until the separate admin secret and allowed origin are deliberately added.
- An isolated dev-Neon test confirmed the site-admin credential can add, pause, and resume a site but cannot insert terms, site state, URLs, or events. The same test sent an authenticated same-origin WSGI POST through the real application and confirmed the second site was persisted; it passed **1/1** (39.64 seconds). The original reader-role query/permission regression also passed **1/1** (50.19 seconds).
